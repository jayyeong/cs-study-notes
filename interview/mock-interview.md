# 네트워크 모의면접

## 진행 방식

한 세트 20분: 기본 질문 5분, 꼬리질문 7분, 상황형 5분, 피드백 3분입니다. 답변이 끝나기 전에 모범 답안을 읽지 않습니다. 면접관은 한 번에 하나씩 질문하고, 정답 단어를 유도하기보다 이유와 조건을 묻습니다.

| 점수 항목 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 정확성 | 핵심 오류 | 정의는 맞지만 예외 누락 | 원리와 조건 정확 |
| 연결성 | 키워드 나열 | 두 개념 연결 | 전체 흐름 연결 |
| 사례 적용 | 적용 불가 | 가설만 제시 | 관측·검증 방법 제시 |
| 전달력 | 결론 불명확 | 장황하나 전달 | 결론 먼저, 구조적 답변 |
| 한계 인식 | 모르는 것 단정 | 질문 후 수정 | 가정·불확실성 명시 |

총 10점입니다. 8점 이상이어도 핵심 오류가 있으면 해당 주제를 다시 복습합니다. 점수는 채용 결과 예측이 아니라 복습 우선순위용입니다.

## 세트 A — 한 패킷의 여행

1. IP와 MAC이 모두 필요한 이유를 설명하세요.
2. PC와 서버가 다른 서브넷이면 ARP로 누구의 MAC을 찾나요?
3. 스위치가 목적지 MAC을 모르면 어떤 일이 일어나나요?
4. 라우터를 지나면서 유지되는 것과 바뀌는 것은 무엇인가요?
5. 상황: 같은 사무실 PC끼리는 통신되는데 외부 접속만 실패합니다. 가설 3개와 확인 순서를 제시하세요.

<details>
<summary>면접관 확인 포인트</summary>

- 최종 목적지 IP와 다음 홉 MAC 구분, 같은 VLAN/IPv4 가정
- 출발지 MAC 학습과 목적지 MAC 조회 구분
- 경로·기본 게이트웨이·외부 DNS/방화벽 문제를 후보로 제시
- 외부 접속 실패만으로 특정 원인을 확정하지 않기

</details>

## 세트 B — 전송은 됐는데 처리는 됐을까?

1. TCP가 바이트 스트림이라는 말의 의미는 무엇인가요?
2. `SEQ=2001`에서 300바이트를 연속 수신했다면 ACK는 무엇인가요?
3. 수신자가 데이터를 읽지 않으면 송신자에게 어떤 제한이 생기나요?
4. CLOSE-WAIT가 증가할 때 어떤 코드를 확인하겠나요?
5. 상황: 주문 요청 전송 뒤 응답 타임아웃이 났습니다. TCP가 신뢰적이므로 바로 재요청해도 되나요?

<details>
<summary>면접관 확인 포인트</summary>

- 앱 메시지 경계와 read/write 횟수 구분
- ACK=2301, 누적 수신 가정 설명
- rwnd·앱 읽기 속도·버퍼 구분
- 상대 FIN 후 로컬 자원 정리 확인
- 서버 처리 결과의 불확실성과 중복 주문 방지 설계

</details>

## 세트 C — 웹 서비스 운영

1. HTTPS URL 입력 이후 화면이 보일 때까지 설명하세요.
2. DNS 응답이 512바이트를 넘으면 어떻게 되나요?
3. HTTP 무상태와 로그인 유지가 함께 가능한 이유는요?
4. TLS 1.3에서 RSA 키 전달을 사용하나요?
5. 상황: 서버를 한 대에서 세 대로 늘린 뒤 로그인이 간헐적으로 풀립니다. 무엇을 관측하겠나요?

<details>
<summary>면접관 확인 포인트</summary>

- 캐시·기존 연결·HTTP 버전에 따른 단계 생략과 변경
- EDNS·TC 비트·TCP 재질의의 관계
- 쿠키와 서버 세션의 조합
- TLS 키 교환과 인증서 서명 구분
- 요청 쿠키, 처리 서버, 세션 저장 위치, 만료를 함께 조사

</details>
